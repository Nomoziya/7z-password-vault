# 恢复事务协议

本功能按 `restore-previous-version-plan.md` 实施；首期入口是设置页按钮，只恢复当前库的 v4 `.bak`。

## 状态与提交点

`CPasswordVaultRestore::Prepare` 记录当前文件存在性和原始字节，读取备份快照，再通过生产读取/解密器认证相同字节。缺失备份明确失败。备份使用独立的只读快照对象，不能调用 `Save`。验证前清除旧缓存，验证结束和恢复退出都清除主密码缓存。

准备成功后由界面展示备份信息并等待确认。`Commit` 是单次调用：取得主库保存互斥锁、核对规范路径、固定父目录句柄，再取得恢复独占会话句柄。重新核对两份文件，先创建并验证恢复前副本，再创建、刷盘、关闭及回读验证恢复临时密文。最终再次核对路径与两个文件，原子替换主文件。

主文件替换是唯一提交点。`Committed` 独立表示是否已提交；`Stage`、`SystemError` 记录失败位置和即时错误码。替换后不再分配条目、解密或询问密码；界面采用已验证的模式并只更新该项注册表值。注册表更新失败报告“文件已恢复，但设置刷新失败”，不会尝试反向覆盖文件。

当前文件损坏但可读取时按原始字节保留，不先解密它；当前文件不存在时省略安全副本，发布时不使用覆盖标志。准备和提交核验当前文件大小上限为现有密码库密文上限加头部余量；超限文件不自动恢复，保留原文件并报错。

## 跨进程会话协调

`<库路径>.session.lock` 是空文件，不含密码、条目或凭据。打开可编辑库时，在原有规范路径互斥锁内以 `GENERIC_READ / FILE_SHARE_READ` 打开它；句柄与密码库对象同生命周期。路径更换、读取失败及析构释放句柄。共享句柄允许多个普通会话加载和保存，原有保存合并仍生效。

恢复在相同主库互斥锁内以 share-none 打开同一协调文件。有任何活跃会话则立即拒绝恢复。操作系统在进程终止时释放句柄，不需要不可靠的 PID 计数或进程通知。不同库使用不同文件；父目录别名落到相同实际协调文件。协调文件拒绝重解析点、多硬链接、目录和非空内容。

协调文件长期保留，不在窗口关闭时删除，避免旧句柄与新文件分离。新目录首次编辑使用需要创建它的权限。导入源和恢复源使用明确的只读快照模式，不创建协调文件且禁止保存，保留只读介质导入能力。v1.5.0 及更早程序不参加此协议，界面提示恢复前关闭旧版程序；不声称能阻止旧版或外部工具直接改文件。

锁顺序：普通加载/保存取得自己的主库互斥锁后打开共享会话；恢复提交取得主库互斥锁后打开独占会话。备份认证不持有主库互斥锁，提交时必须复核备份是否变化。失败不终止占用进程；已有会话保留原条目，可在关闭窗口后重新恢复。

## 文件与权限

- `.bak` 是只读恢复来源，恢复过程不轮换或写入它。
- `.pre-restore-<UTC日期>-<随机ID>` 为独占创建的恢复前文件副本。完整验证后永久保留，即使随后替换失败也保留。
- `.restore-tmp-<相同唯一标识>` 仅包含已验证的备份密文；正常退出时尝试删除本次临时文件。进程被强制终止可留下临时密文，绝不自动用它覆盖当前库。
- 恢复前副本和目标临时文件在写入字节前应用当前文件的 DACL，并禁止额外继承权限。主文件不存在时使用所在目录的默认继承权限。
- 所有发布使用同卷文件替换，不先删除当前库。不提供任意存储设备断电下的绝对原子性保证。

读取真实文件、认证和保存均有现有边界限制。路径检查、句柄属性、父目录固定和最后复核防止普通路径替换问题；本方案不将同账户恶意外部进程视为可通过应用锁隔离的安全边界。

## 验证证据

原生测试直接包含生产实现。新增用例覆盖事务结果、备份保持、读取快照禁止保存、旧密码与取消、恢复冲突、跨进程共享会话、崩溃释放、替换前后进程中断、真实 ACL 拒绝及原有 200 次并发保存。真实磁盘满脚本已增加实际恢复事务断言。

完整执行记录及未完成范围见 `restore-validation.md`。历史版本通过结果不替代本功能的 GUI、真实磁盘及发布验收。
