## 已落实

| 评审事项 | 实现与边界 |
| --- | --- |
| 双进程丢数据 | 规范化绝对路径并解析父目录别名，建立 Global 命名 mutex。读取和写入均参与互斥；保存锁覆盖读取最新库、差异合并、临时写入、刷盘和替换。独立修改合并，同条冲突明确失败。 |
| 文件版本比较 | 保存时比较完整文件字节，不依赖时间戳或大小。同名并发新增拒绝合并；删除原文件不允许从旧快照重建。 |
| 保存失败回滚 | 核心 Save 提供回滚保护；候选对象写入成功后才提交活动状态。UI 原有失败恢复保留。 |
| 假自动锁定 | 采用评审允许的降级方案：中英繁体文案均改为缓存到期，明确不锁定已打开的库。下次索取缓存密码时检查 5 分钟有效期。本版不宣称自动锁定。 |
| 明文生命周期 | 敏感字段增加拥有型 RAII 字符串；旧值替换和析构清理。解密缓冲和派生密钥采用 RAII 擦除；CBuffer::Wipe 改为 volatile 写入；DPAPI 系统返回明文在释放前清零。 |
| DPAPI 结构认证 | 新格式 v4 整体加密认证。v2/v3 只读迁移，新保存只写 v4；拒绝异常长度、无效标记和尾随数据。 |
| 默认位置与迁移 | 默认用户 APPDATA，显式选择程序目录或自定义位置；不自动移动。迁移只写新目标并保留旧库；已有目标须通过导入合并。 |
| 主密码确认 | 设置按钮和开启模式的勾选框都要求两次输入；错误/取消不覆盖原库，错误缓存失效后可重新输入。 |
| 写入耐久性 | 临时文件排他新建、写穿、FlushFileBuffers、MoveFileEx 写穿替换；一般失败/异常路径清理临时文件。崩溃留下的加密临时文件不自动作为正式库采用。 |
| 发布内容 | 空 staging、逐文件白名单、递归检查隐藏文件与重解析点、固定输入哈希。只发布 ZIP，3 个语言文件；移除首启登记和设置页安装入口，构建中移除 SetupShortcuts 模块。 |
| 发布证据 | 公开打包模式要求已核验的输入锁、干净源码和绑定当前 EXE 哈希的标准用户 GUI、升级回滚结果；独立 ZIP SHA-256、构建记录、源码清单和包内文件 SBOM。扫描状态如实记录，旧误报记录不为新构建背书。 |

## 本机验证

- 7zFM.exe / 7zG.exe 以 GCC 16.2.0 和项目现有 `-Werror` 配置构建。
- 原生测试执行实际生产密码库代码和 Windows DPAPI/AES；对话框与设置使用测试适配器，不访问真实密码库或用户设置。
- 两个独立测试进程各连续保存 100 次，200 条新增全部保留。
- 验证新库并发、同条编辑冲突、删除与独立新增合并、相同大小/时间戳的修改、错误主密码、取消解锁/保存、主密码与 DPAPI 切换、缓存过期语义，以及关闭“记住主密码”后消费并擦除单次保存缓存。
- 验证密文篡改、合法加密但内部结构损坏、尾随数据、文件独占锁、保存失败回滚、替换前进程退出，以及 v2/v3 → v4 升级。
- 磁盘满和替换权限拒绝通过 Win32 API 故障注入验证；不等于真实磁盘/ACL/断电验收。
- 压缩/解压引擎回归 39 项通过；最终 ZIP 的独立哈希、解包文件集合和逐文件哈希核验通过。
- 当前发布门禁回归 32 项通过，包含敏感文件、子目录、隐藏文件、junction、清单穿越/重复/缺失、哈希篡改、拒绝 SFX、未签名候选的证据绑定、Windows 11 Insider 字段及 ZIP 解包复核。
- 当前执行环境的 DPAPI 在隔离身份下不可用，原生加密测试已在获准的普通用户环境运行。

## 仍然阻断公开发布

1. 项目长期未签名；当前 review4 仍明确使用 `internal-test` 文件名。哈希和 sidecar 不能认证发布者。
2. review4 未做当前最终哈希的 Defender 复核；本轮未上传文件，也未复用旧哈希结论。门禁允许如实记录 `not-reviewed`。
3. 上游源码归档与 8 个运行时文件的官方来源已核验；但 review4 构建时源码有未提交改动，未在干净提交及全新 CI 环境复现构建。
4. 当前目标系统仅为 Windows 11 Insider。`Nomozi` 桌面和独立 `cs` 标准账户的 review3→review4 隔离库升级回滚均通过 393/393，结果各自留存。原生双进程测试不代替 GUI 验收。
5. 当前目标系统上的真实满盘及 ACL 拒绝已通过；断电、跨文件系统/网络路径的专项验收尚未完成。

内存清理不能保证清除系统分页、控件或其他模块内的所有明文副本；本版不提供真正自动锁定。便携库路径须显式设置，主密码为跨设备使用的建议配置，未强制禁止自定义路径上的 DPAPI。

后续验收应以 BUILD.md 的流程生成全新候选包，对同一组最终 EXE 哈希完成标准用户 GUI 与升级回滚测试，记录实际扫描状态后再决定放行。历史设计/发行记录只用于追溯。
