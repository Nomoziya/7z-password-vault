# 长期未签名发布策略

项目已决定长期发布未签名 portable ZIP，不购买代码签名证书，也不把自签名证书当成公开信任。review4 是历史受控内测包；当前版本只保证 Windows 11 Insider x64 范围，公开发布仍须通过来源、干净源码、同哈希 GUI、升级回滚和包完整性门禁。

## 发布内容与验证

- 最终 ZIP 的 SHA-256、独立 `.sha256`、包内 `SHA256SUMS.txt`、`.build.json` 和 `.sbom.json`。
- 上游源码归档与每个运行时输入的独立核验记录，以及干净、已提交的源码版本。
- 绑定当前两个 EXE 哈希的 Windows 11 Insider 标准用户 GUI 和隔离密码库升级回滚验收原始记录。
- 两个 EXE 的实际签名状态及安全扫描状态；未扫描写 `not-reviewed`，环境不可用写 `scan-unavailable`。

用户应从独立确认的项目发布渠道取得 ZIP 和公布的 SHA-256，再核对下载文件。与 ZIP 同目录的 sidecar、清单和构建记录可一起被替换，只能证明相互一致，不能证明发布者身份。未签名文件可能出现首次运行警告或误报，不能承诺没有误报；不得要求用户关闭 Defender、添加排除项或降低 SmartScreen 设置。

如发生误报，可由开发者经 Microsoft Security Intelligence 的 Software developer 入口提交**当前最终文件**供复核；历史哈希或历史结论不适用于新构建。本轮按用户决定不上传样本，也不把未扫描状态描述为 clean。

## 执行顺序

1. 继续使用 `internal-test` ZIP 完成受控测试。
2. 独立核验上游输入并保存出处、哈希和原始证据；在干净、已提交的源码树中构建候选包。
3. 对相同候选 EXE 哈希完成 Windows 11 Insider 标准用户 GUI 与隔离密码库升级回滚验收。
4. 将安全扫描状态如实写入验收记录；已知检出不得作为通过。
5. 来源和验收门禁都通过后，才可移除 `internal-test` 标识；公开说明仍须写明未签名、哈希校验的局限和扫描状态。

具体字段与命令见 [BUILD.md](../BUILD.md)。
